[A1] — Toolchain: uv 0.12.17 (brew), Python 3.11.16 via `uv python install`, gitleaks 8.30.1 (brew), Node 24.6.0 (Node 20 is end-of-life; the Integration Owner pinned "Node 24 LTS" in the docs, commit f56f1ac). pre-commit is a workspace dev dependency in the root pyproject (pinned by uv.lock, installed by `uv sync`, then `uv run pre-commit install`), not a `uv tool`, so all machines get the same version.
[A1] — import-linter can only resolve forbidden external packages that are installed, so sqlalchemy, fastapi, httpx and requests sit in the root `dev` dependency group purely for the domain-purity contract. Runtime dependencies are added per step. Facade-only rule = one forbidden contract per module with `nakabandi.<other>.**` and `allow_indirect_imports = True`; layers contract marks `interfaces` and `infrastructure` optional because not every module has them. All 17 contracts were shown to fire on deliberate violations; a facade import correctly passes.
[A1] — NOT encoded: the DOC 2 §2.6 row "only evaluation may import the oracle client". `nakabandi.evaluation.oracle_client` does not exist yet (Track B, B7), and a forbidden contract needs the module to exist. Until then the facade rule already blocks every non-evaluation module from reaching it, and `main.py` may not import evaluation. Add an explicit contract when B7 creates the file. Also not encodable: "only pipeline and main.py import several facades in sequence"; only "no module imports pipeline" is enforced.
[A1] — eslint-plugin-boundaries 7.2 uses the `boundaries/dependencies` rule with `policies` (not the old `element-types`). It silently skips extensionless TypeScript imports unless `settings["import/resolver"] = { node: { extensions: [".ts", ".tsx"] } }` is set; without it the cross-feature rule reported nothing at all. No extra resolver package was needed (eslint-import-resolver-node ships with the plugin). Always test a boundary rule with a deliberate violation before trusting a green lint.
[A1] — Root scripts `dev`, `types`, `seed`, `reset`, `sweep` are placeholders (`scripts/not-yet.mjs`, exit 0 with a message) until their steps land. `.env.example` lives in infra/ (DOC 2 layout) and lists only the four bank-sim names DOC 3 defines; API Settings names are added at A2.
[A1] — Shell gotcha: the dev shell is zsh, which does not word-split unquoted variables, so `for m in $list` loops and `uv run "cmd args"` silently misbehave. Use literal lists or arrays.
[A2] — LC-7 names every policy.yaml key but gives a literal starting value for only a few (forecast.horizons_min [30,60,120]; forecast.candidates.max 200; forecast.novelty_threshold 0.7; interception.thresholds.interceptable/marginal 0.7/0.3; interception.targets 3; alerting.delivery.max_attempts 5 and backoff_s 5, from "5 s, 10 s, ... capped 5 min"). Every other numeric leaf (radius_km, abstain thresholds, speed_kmh, severity_bands, budget_per_shift, k_threshold, amount/confidence bands, label_rate, ...) has no DOC3 source and is a Track-A-authored starting value, the same way Appendix A treats simulator priors: a seed for Track B to calibrate and sweep, not a fact. config/policy.yaml's header comment marks which is which; do not read an unmarked value as calibrated.
[A2] — Policy.load() aborting on both an unknown key and a missing one (pydantic `extra="forbid"` plus no field defaults) means it also aborts on a key DOC3 names but a value-writer forgot to fill in — that's deliberate: a silently-defaulted policy key is worse than a boot failure naming the exact path.
[A2] — Two locked contracts (LC-1, LC-2) live in packages/contracts, which the import-linter contract "contracts-are-leaf" forbids from importing `nakabandi`. So SimTime's tz-aware-UTC rule (LC-2) is implemented twice, once in `nakabandi_contracts.ingest` and once in `nakabandi.shared.types`, deliberately not shared as one symbol — this is a boundary consequence, not duplication to clean up later.
[A2] — Extended `.importlinter` with a "shared" facade contract (other modules may import `nakabandi.shared` but not `nakabandi.shared.<file>`), mirroring the existing per-module facade contracts. DOC2 §2.6's facade rule names "another module" generically and shared is explicitly "the only code every track imports" (DOC3 Shared Kernel), so the same protection was extended to it; A1 had not, since shared had no content yet. Flagged for the Integration Owner because it's a boundary-config change, not just new files under the step's named folder targets.
[A2] — `npm run types` now runs scripts/gen_contract_schemas.py then `git diff --stat --exit-code` on the schemas folder; against untracked files git diff is a no-op (always exits 0), so the check only does real work once the schemas are committed/staged. Verified both directions with the files staged: changing the ingest.py model without regenerating makes `npm run types` exit 1 with a diff shown; regenerating brings it back to exit 0. When checking a "no diff" claim like this, confirm the files are tracked/staged first, or the check is vacuous.

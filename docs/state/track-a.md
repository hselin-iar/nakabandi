[A1] — eslint-plugin-boundaries 7.2 uses the `boundaries/dependencies` rule with `policies` (not the old `element-types`). No extra resolver package was needed (eslint-import-resolver-node ships with the plugin). Always test a boundary rule with a deliberate violation before trusting a green lint.

[A3] — Seeding `SimClock`'s boot value from wall-clock `now()` (via `SystemClock`) is a trap: `advance_to` is monotonic and silently ignores a target earlier than current, so any demo/seed data dated before the moment the process happens to boot would freeze the clock forever with no error. Fixed by seeding from a fixed Unix-epoch constant instead (`shared.SIM_CLOCK_EPOCH`, in `shared/clock.py`, exported through the facade) so the first real batch always advances it forward. Caught by actually running `npm run seed` end-to-end, not just by the pytest suite (which never asserted on `response.sim_time`) — a green test suite did not catch this; running the real CLI path did.
